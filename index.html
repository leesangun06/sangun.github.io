어떻게 공정하게 측정하나요?

동일한 순서로 섞은 입력을 두 알고리즘에 복사해 제공합니다. 각 알고리즘을 3회 예열하고, 실행 순서를 번갈아 가며 9라운드 측정합니다. 작은 입력은 한 라운드에서 여러 번 정렬해 1회당 평균을 구한 뒤, 9개 평균의 중앙값을 표시합니다. 입력 생성·복사·화면 그리기는 측정에서 제외하며, 알고리즘 내부의 작업 공간 할당은 포함합니다. 비교 횟수는 별도 1회 실행에서 셉니다.

performance.now()를 사용합니다. 기기·브라우저·백그라운드 작업에 따라 결과와 우열이 달라집니다. 짧은 실행 시간은 타이머 정밀도의 영향을 크게 받습니다. 이 실험만으로 일반적인 우열을 결론 내릴 수 없습니다.

    02 / UNDER THE HOOD

    같은 정답으로 가는 두 가지 길

    먹는 즐거움에, 배우는 재미를 더해서.
    01

    Merge Sort 병합 정렬

    작은 묶음부터 정렬하고, 이웃한 두 묶음에서 앞선 항목을 골라 합칩니다. 이 과정을 반복하면 전체가 정렬됩니다.

    시간 O(n log n)추가 공간 O(n)
    [비빔밥 · 김밥]→[김밥 · 비빔밥]

    이 사이트는 반복형 병합 정렬을 직접 구현했습니다. 같은 키는 왼쪽 항목을 먼저 선택해 안정성을 유지합니다.

    02

    Quick Sort 퀵 정렬

    피벗을 기준으로 작은 값·같은 값·큰 값을 나눕니다. 나뉜 구간에 같은 과정을 반복해 제자리를 찾아갑니다.

    평균 O(n log n)최악 O(n²)
    작은 값←피벗→큰 값

    이 사이트는 가운데 값을 피벗으로 삼는 반복형 3-way 분할을 사용합니다. 작은 구간부터 처리해 보조 스택을 O(log n)으로 제한합니다. 안정 정렬은 아닙니다.

    버튼에서 실제 함수까지

    선호도순·가나다순 버튼 → app.js의 setOrder() → renderMenus() → 선택한 알고리즘에 따라 algorithms.js의 mergeSort() 또는 quickSort()를 호출합니다. 시간 비교 버튼 → runExperiment() → runBenchmark() → 동일한 기준으로 두 함수를 모두 호출합니다. 가나다순은 Intl.Collator('ko')로 비교하며, 동률은 레코드 ID로 결정합니다.

    실험 기록과 과제 제출 파일

    측정을 완료한 뒤 배포된 Netlify 주소를 입력하면, 실제 측정값이 담긴 submission.txt를 내려받을 수 있습니다.
